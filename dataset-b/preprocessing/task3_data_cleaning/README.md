# Task 3 — Data Cleaning

> **Phase 2: Data Preparation | Dataset B (Boreal Watchtower/Drone)**

## Objective

Remove corrupt/empty images, validate label format compliance, detect near-duplicates, identify annotation quality issues — without modifying ground truth.

## Strict Policy: Zero Imputation

For object detection with bounding boxes, we cannot "impute" missing pixels or hallucinate missing annotations. All integrity issues are handled via **listwise deletion** for corrupt files and **flagging** for quality concerns.

## 7-Part Cleaning Pipeline

| Part | Check | Method | Issues Found |
|------|-------|--------|-------------|
| 1 — Missing Values | Image-label pairing, file integrity | PIL.verify(), 0-byte check, stem cross-reference | 5 unpaired images identified |
| 2 — Exact Duplicates | Byte-identical files | MD5 hash | TBD |
| 3 — Noisy Data & Outliers | BBox area, aspect ratio, blur, contrast | Percentile bounds (skewed data), IQR (normal), Laplacian variance | 26 area outliers, 368 AR outliers, 431 blurry frames |
| 4 — Consistency & Validity | YOLO format, coordinate bounds, class ID | 5-float validation, 2-tier clipping (margin <0.02 clip, ≥0.02 delete), pixel-space bounds | 2 coordinates auto-corrected |
| 5 — Sequential Consistency | Video-aware checks | Consecutive frame IoU, 3-frame interpolation, pHash near-duplicates | 255 temporal jumps, 3,389 near-duplicates |
| 6 — Data Drift | Temporal, illumination, spatial | Task 2 findings mapped to rubric | Day vs night, top 40% horizon |
| 7 — Cleaning Log | Full audit trail | Pandas DataFrame per modification | 4,139 entries |

## Engineering Challenges & Corrections

### The IQR Failure on Skewed Box Areas

Our initial approach applied the standard IQR method (Q1 - 1.5×IQR, Q3 + 1.5×IQR) to bounding box areas to detect outliers. This was a mistake: the box area distribution is heavily right-skewed (95.7% of plumes occupy >10% of the image). IQR assumes approximate normality and **erroneously flagged legitimate large smoke plumes as outliers**. We caught this during review and switched to asymmetric percentile bounds — flagging only the bottom 0.5% (tiny, likely degenerate boxes) and top 99.5% (boxes covering the entire frame, likely annotation errors). This saved the large plume data from false deletion while still catching genuine anomalies.

### pHash Near-Duplicate Policy

3,389 near-duplicate frames were detected (pHash Hamming distance < 5). These are NOT deleted — they are flagged and documented. The handling occurs in Task 4 via `--max-frames-per-clip` frame sampling, not via destructive cleaning.
