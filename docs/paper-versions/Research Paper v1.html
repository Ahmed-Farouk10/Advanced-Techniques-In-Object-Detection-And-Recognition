Project Proposal: Advanced Edge-Optimized Forest Fire Object Detection

Team: Esraa Nasr and Ahmed Ayman

Selection of Application Category: Forest Fire & Environmental Disaster Management

Review: Current Challenges and Research Trends

Traditional forest fire detection models focus purely on drawing bounding boxes around smoke or flames. This approach suffers from two major bottlenecks: heavy models cannot run on cheap drones, and fast edge models trigger too many false alarms (confusing clouds or glare for fire).

The Novel Discovery Angle: This project proposes a "Cognitive Fire Defense Pipeline"—an asymmetric Edge-Cloud hybrid architecture tailored for real-world compute limits. Because remote forest environments lack heavy server access, our research restricts compute power to simulate real-world constraints. We will conduct two experiments across two data distributions to prove that a lightweight edge model acting as the Sentinel (fast reflexes) can be effectively paired with a zero-shot semantic pipeline acting as the Commander (deep thought and threat triage) to achieve high accuracy without requiring heavy enterprise GPUs.

Selection of Object Detection Models

To derive new insights, we selected four models representing fundamentally different architectural philosophies, modified specifically for low-compute environments.

Experiment 1: The Micro View (Dataset A - Drone/UAV Imagery)

Environment: Dynamic, moving cameras, top-down angles, requiring high processing speed on low-power edge devices.

Goal: Discover if modern single-stage Nano models outperform lightweight two-stage models for dynamic edge deployment.

  1. The Modern CNN Edge Standard: YOLO11n (Nano)
    • Architecture Family: One-Stage Detector.
    • Why it’s in the stack: Designed specifically for extreme edge devices. Highly accessible via the "Ultralytics" Python package. It tests the baseline of speed and memory efficiency against motion blur.
  1. The Two-Stage Lightweight: Faster R-CNN (via Detectron2)
    • Architecture Family: Two-Stage Detector (RPN + Classification).
    • Why it’s in the stack: Standard Faster R-CNN is too heavy. By replacing its backbone with MobileNetV3, we retain the stable Region Proposal Network (RPN) to test if two-stage localization handles complex forest backgrounds better than YOLO, without bottlenecking hardware.

Experiment 2: The Macro View (Dataset B - Watchtower/Panoramic Imagery)

Environment: Static cameras, extreme distances, heavy environmental noise (clouds, haze, sunsets).

Goal: Determine whether lightweight visual transformers or zero-shot semantic prompting is more efficient at eliminating false positives at long distances.

  1. The Transformer-Based Pioneer: Swin-T (Tiny)
    • Architecture Family: Hierarchical Vision Transformer (ViT).
    • Why it’s in the stack: Tests if the hierarchical windowing logic of transformers can process high-resolution landscapes and spot tiny distant anomalies efficiently on standard hardware.
  1. The Semantic Hybrid: EfficientDet-D0 + OWLv2
    • Architecture Family: Lightweight CNN + Semantic Zero-Shot Text-to-Vision.
    • Why it’s in the stack: EfficientDet handles the low-compute visual scanning. OWLv2 is used without training (zero-shot inference only) to semantically filter false alarms (e.g., prompting the model to distinguish "clouds" from "smoke") based on pre-trained linguistic knowledge, bypassing the need for heavy cloud training.

Dataset Preprocessing

Forest fire data presents unique challenges that require strict preprocessing:

  • Analyze dataset characteristics:
    • Number of classes: 2 (Fire, Smoke).
    • Object distribution: Addressing severe class imbalance (massive areas of background forest vs. tiny patches of early smoke).
    • Annotation formats: YOLO TXT format and COCO JSON format.
    • Image resolutions: Resizing extreme 4K watchtower images down to $416 \times 416$ or $512 \times 512$ to survive low-VRAM training.
    • Potential challenges: Occlusion (smoke hidden by tree canopies), environmental mimics (fog, low-hanging clouds), and small object detection.

Hyperparameters

Hyperparameters control how the model learns.

  • Learning Rate: Controls the speed of learning. (Too high $\rightarrow$ unstable training; Too low $\rightarrow$ slow learning).
  • Weight Decay: Regularization technique to help reduce overfitting.
  • Momentum: Improves optimization stability and speed.
  • IoU Threshold: Determines whether a predicted bounding box is considered correct.
  • Confidence Threshold: Minimum confidence required to accept a detection.

Performance Evaluation

This is the most important part of the project. We will compare all models scientifically using standard evaluation metrics.

A) Precision

Measures: “How many predicted detections are actually correct?” High precision means fewer false detections (fewer fire trucks dispatched by mistake).

$$Precision = \frac{TP}{TP + FP}$$

(Where: TP = True Positives, FP = False Positives)

B) Recall

Measures: “How many real objects were successfully detected?” High recall means the model misses fewer objects (no fires go unnoticed).

$$Recall = \frac{TP}{TP + FN}$$

(Where: FN = False Negatives)

C) F1-Score

Balances Precision and Recall.

$$F1 = 2 \times \frac{Precision \times Recall}{Precision + Recall}$$

D) IoU (Intersection over Union)

Measures how well the predicted bounding box overlaps with the ground-truth box.

$$IoU = \frac{Area \ of \ Overlap}{Area \ of \ Union}$$

E) Inference Speed (FPS)

FPS (Frames Per Second) measures how fast the model processes images. Highly important for the drone (Dataset A) to achieve real-time live video analysis.

F) Model Size & Computational Complexity

  • Model Size (MB): Storage footprint of the trained weights.
  • Complexity: Evaluated using FLOPs (Floating Point Operations) and Parameter count to prove viability for edge hardware.

Final Analysis and Discussion

The final project deliverable will not just declare a single "winner." We will explain the strengths and weaknesses of each model based on the two experiments:

  • Did YOLO11n achieve the highest inference speed without sacrificing critical recall?
  • Did Faster R-CNN localize small smoke plumes better due to its two-stage RPN?
  • Did the OWLv2 Semantic Pipeline successfully eliminate distant atmospheric false alarms better than the Swin Transformer?

Overall Goal of the Project:

Beyond running algorithms, we are expected to compare them scientifically, analyze accuracy vs. speed vs. compute-cost trade-offs, and present our final discovery: The Cognitive Fire Defense Pipeline. By proving that lightweight visual algorithms can be paired with zero-shot linguistic reasoning, we will offer a highly practical, low-compute blueprint for modern disaster management.
